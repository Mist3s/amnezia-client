# HomeVPN

Форк [AmneziaVPN](https://github.com/amnezia-vpn/amnezia-client) для своих устройств.
Главных отличий от оригинала два:

1. **Конфиг с бэкенда.** Приложение само забирает актуальный конфиг AmneziaWG со своего бэкенда:
   по кнопке, по расписанию и перед подключением. Сменили сервер на бэкенде — устройства переехали сами.
2. **Обновления с бэкенда.** Новая версия приложения скачивается со своего бэкенда и ставится
   только после проверки sha256 из манифеста.

Ещё несколько мелких:

- **Список серверов с бэкенда.** Бэкенд выдаёт устройству несколько серверов и говорит, какой основной.
  Приложение добавляет новые, обновляет изменённые и убирает снятые; серверы, добавленные вручную, не трогает.
  Человек может выбрать другой сервер из списка — выбор сохраняется, пока основной не сменят на бэкенде.
- **Автозапуск.** На устройстве с настроенным бэкендом один раз включаются «Автозапуск» и «Автоподключение»
  (Настройки → Приложение, там же их можно выключить). На Android автозапуск — это включение VPN при загрузке
  устройства с последним использованным сервером; окно приложения при этом не открывается.
- **Пульт телевизора.** Рамка выделения на Android толще; на телевизоре при открытии страницы сразу выделен
  её первый элемент (на главной — кнопка подключения).
- **Плитка быстрых настроек Android** (там же, где Wi-Fi и Bluetooth) подписана названием приложения,
  а не именем сервера; значок — наш.
- **Название и значок на Linux и Windows.** Ярлык, заголовок окна, меню и значок в трее — «ЧихНет».
  Внутренние имена (программа `AmneziaVPN`, служба, папка настроек) оставлены как в оригинале,
  чтобы уже установленное приложение не потеряло настройки.
- **VPN-сервер не отвечает.** Если устройство с настроенным бэкендом не подключилось за 30 секунд или сервер
  перестал отвечать при включённом VPN, VPN выключается и работает обычный интернет. Потом приложение само
  пробует подключиться снова: через 1, 2, 4, 8, 15 минут и дальше каждые 30 минут. На Windows и Linux перед
  каждой попыткой оно спрашивает бэкенд, так что смена сервера в панели подхватывается сразу. На Android за этим
  следит служба VPN, она работает и без открытого приложения. «Отключить» во время попытки прекращает повторы.

Всё остальное работает как в оригинале. Пока адрес бэкенда не задан, приложение ведёт себя как AmneziaVPN.

Бэкенд — отдельный репозиторий `homevpn-backend`. Протокол: HTTPS + JSON, у каждого устройства свой ключ.

## Как настроить устройство

### Файлом настройки (проще всего)

В панели админа при выдаче ключа устройства есть кнопка **«Файл настройки»**. Файл `chihnet-ИМЯ.vpn`
открывают в приложении как обычный конфиг: «+» → **«Файл с настройками подключения»**. Приложение само
получает конфиг с бэкенда и добавляет сервер, который дальше обновляется сам. Больше ничего вписывать не надо.

То же самое делает строка из кнопки «Скопировать строку», если вставить её в поле **«Вставьте ключ»**.
На Android файл можно открыть и из проводника («Открыть с помощью»), а на приставку — отправить по adb
(команда для Linux, файл настройки лежит в текущей папке):

```sh
adb shell "am start -n dev.homevpn.app/org.amnezia.vpn.ImportConfigActivity \
    -a android.intent.action.SEND -t text/plain --es android.intent.extra.TEXT '$(cat chihnet-ИМЯ.vpn)'"
```

Внутри файла — JSON `{"backend": "https://ДОМЕН", "key": "КЛЮЧ_УСТРОЙСТВА"}`. Если на устройстве уже есть
сервер с этого бэкенда, второй не создаётся: у существующего меняется ключ. В файле лежит ключ устройства —
после настройки его надо удалить.

### Вручную

1. Установить HomeVPN.
2. Добавить сервер обычным способом — импортировать любой рабочий `.conf` AmneziaWG.
3. Настройки сервера → **«Автообновление настроек»**: вписать адрес бэкенда (`https://…`, можно несколько через запятую)
   и ключ устройства, нажать **«Сохранить»**, затем **«Обновить сейчас»**.

Названия даны для русского языка приложения. В английском это File with connection settings, Insert key,
Config auto-update, Save и Update config.

Дальше приложение обновляет конфиг само. Бэкенд недоступен — работает последний полученный конфиг,
соединение не рвётся. Если новый конфиг пришёл при включённом VPN — приложение переподключится.

### Компьютер с Windows: одним файлом

В панели админа при выдаче ключа устройства есть кнопка **«Файл для Windows»**. Файл `chihnet-ИМЯ.cmd`
запускают на компьютере двойным щелчком. Он берёт с бэкенда скрипт `/setup/windows.ps1`, а тот:

1. спрашивает у бэкенда последнюю версию и скачивает установщик;
2. сверяет sha256 с манифестом (`Get-FileHash`) и при несовпадении ничего не ставит;
3. запускает установщик — в нём надо нажать Next / Install и согласиться на вопрос Windows;
4. запускает приложение с адресом бэкенда и ключом: оно само получает конфиг, добавляет сервер,
   подключается и включает автозапуск с автоподключением.

Повторный запуск того же файла ничего не ломает: если версия уже стоит, установка пропускается.
В файле лежит ключ устройства — после установки его надо удалить.

### Настройка без рук: `--managed-setup`

Скрипт для Windows опирается на параметр запуска `--managed-setup ФАЙЛ`. В файле — JSON:

```json
{"backend": "https://ДОМЕН", "key": "КЛЮЧ_УСТРОЙСТВА", "connect": true, "autostart": true}
```

Приложение читает файл, сразу удаляет его, получает с бэкенда конфиг и добавляет сервер, который дальше
обновляется сам. `connect` — подключиться после настройки, `autostart` — включить автозапуск и автоподключение
(если в файле `autostart` нет или он `false`, приложение само их не включит).
Если сервер с этого бэкенда уже есть, второй не создаётся. Параметр работает только при старте приложения:
если оно уже запущено, его надо сначала закрыть.

## Как собрать

Проще всего собирать на GitHub — см. «На GitHub: все сборки сразу». Ниже — как собрать у себя.
Общее для всех платформ — как в оригинале, см. раздел «Hacking guide» в [README.md](README.md):
Qt 6.10, CMake, Ninja, Conan 2, для Android — SDK, NDK 27 и Java 17.

### Версия

Версия HomeVPN = версия оригинала, где последнее число умножено на 100 и к нему прибавлен номер моей сборки.
Оригинал `5.1.1.11`, сборка `1` → `5.1.1.1101`. Номер сборки общий для всех платформ, только растёт
и не сбрасывается, даже когда меняется версия оригинала. Посчитать версию: `homevpn/version.sh 1`.

### Android

Нужен ключ подписи (PKCS12). Он один на все сборки и лежит **вне репозитория**: потеряли ключ —
обновления поверх старых установок перестанут ставиться.

```sh
export HOMEVPN_KEYSTORE=/путь/вне/репозитория/homevpn-release.p12
export HOMEVPN_KEYSTORE_PASS_FILE=/путь/вне/репозитория/keystore.pass
export QT_INSTALL_DIR=/каталог/в/котором/лежит/Qt

homevpn/android-apk.sh 30 arm64-v8a   2   # телефоны, Android 11+
homevpn/android-apk.sh 30 armeabi-v7a 2   # приставки, Android 11+
homevpn/android-apk.sh 28 armeabi-v7a 2   # приставки, Android 9–10
```

Аргументы: минимальный Android SDK (`28` — сборка для Android 9–10, `30` — для Android 11 и новее),
архитектура, номер сборки. Для `28` нужен Qt 6.10.1, для `30` — Qt 6.10.3 (так же собирает оригинал).
Готовый файл: `deploy/build-homevpn/out/HomeVPN_<версия>_<abi>_api<sdk>.apk`. Рядом ложится `<имя>.apk.json`
с описанием, для каких устройств сборка, — из него собирается список файлов релиза.

Идентификатор приложения — `dev.homevpn.app`, поэтому HomeVPN ставится рядом с AmneziaVPN и не мешает ему.

На устройстве приложение называется **«ЧихНет»**: подпись под значком задаёт `CLIENT_ANDROID_APP_NAME`
в `homevpn/android-apk.sh`, значок, баннер для приставок и одноцветный значок для строки уведомлений
(`drawable-*/ic_stat_homevpn.png`) лежат в `homevpn/android-res/` и при сборке ложатся поверх ресурсов оригинала. Внутреннее имя `HomeVPN` и идентификатор менять нельзя:
на них держатся настройки приложения и установка обновлений поверх.

### Linux

```sh
EXTRA_CMAKE_ARGS="-C $PWD/homevpn/desktop/brand.cmake -DAMNEZIAVPN_VERSION=5.1.1.1102 -DCONAN_HOST_PROFILE=default;auto-cmake;$PWD/homevpn/conan-pin-zlib.profile" \
    deploy/build.sh --generator Ninja --installer all
```

Установщик: `deploy/build/AmneziaVPN_<версия>_linux_x64.run`. Нужен Qt Installer Framework.

Профиль `homevpn/conan-pin-zlib.profile` закрепляет одну версию zlib для всех зависимостей. Без него
`openvpn` и клиент получают две разные сборки OpenSSL, и упаковка установщика падает с ошибкой
`Multiple conflicting paths found for libcrypto.so.3`. Если в кэше Conan уже лежит `openvpn`, собранный
без профиля, его надо удалить: `conan remove "openvpn/*:*" -c`.

### Windows

Собирается только на GitHub (см. ниже). Установщик: `AmneziaVPN_<версия>_windows_x64.exe`.

На ПК человек видит «ЧихНет» и наш значок (ярлык, окно, трей) — это задаёт `homevpn/desktop/brand.cmake`.
Внутри сборка по-прежнему зовётся AmneziaVPN (программа, служба, папка установки и настроек)
и ставится **вместо** официального клиента.

Проверить установщик Windows без своей машины: сценарий **«HomeVPN Windows check»** ставит выпущенную версию
на машине GitHub, сверяет названия ярлыков и окна и прикладывает снимки экрана:

```sh
gh workflow run homevpn-windows-check.yml --ref homevpn -f version=5.1.1.1109
```

### На GitHub: все сборки сразу

Actions → **HomeVPN Release** → Run workflow → указать номер сборки. Сценарий
`.github/workflows/homevpn-release.yml` собирает три APK, установщики для Linux и Windows, прогоняет тесты форка
и выкладывает всё релизом `homevpn-<версия>`. В релизе лежит `homevpn-release.json` — имена файлов,
их sha256, для чего каждый и что нового в сборке; по нему бэкенд забирает сборки.
Описание релиза берётся из `homevpn/changelog.json`.

Один раз в настройках репозитория (Settings → Secrets and variables → Actions) задаются секреты для подписи APK:

```sh
base64 -w0 /путь/вне/репозитория/homevpn-release.p12 | gh secret set HOMEVPN_KEYSTORE_BASE64
tr -d '\r\n' < /путь/вне/репозитория/keystore.pass | gh secret set HOMEVPN_KEYSTORE_PASS
```

Если релиз с таким номером уже есть или сборка не описана в `homevpn/changelog.json`, сценарий сразу остановится.

### Тесты

```sh
cmake --build <каталог сборки> --target test_managed_config_policy test_managed_update_policy
ctest -R 'ManagedConfigPolicyTest|ManagedUpdatePolicyTest'
```

## Как выпустить версию

1. Взять следующий номер сборки (на единицу больше прошлого).
2. Записать в `homevpn/changelog.json`, что нового в этой сборке, и отправить на GitHub:

   ```json
   "8": {
     "new": ["Что появилось"],
     "improved": ["Что стало лучше"],
     "fixed": ["Что починили"]
   }
   ```

   Этот список попадёт в описание релиза, в панель и в окно обновления на устройстве. Устройство, которое
   пропустило несколько версий, увидит изменения всех пропущенных. Проверить запись: `homevpn/changelog.py 8 --markdown`.
3. Собрать все варианты: на GitHub — Actions → **HomeVPN Release** → Run workflow с этим номером.
4. В панели админа: Версии → GitHub → **«Подтянуть в панель»**. Бэкенд скачает файлы релиза, сверит sha256
   и опубликует их вместе со списком изменений. Список можно поправить там же: Версии → «Изменить».

   Сборки, сделанные у себя, загружаются вручную — sha256 бэкенд посчитает сам. В панели: Версии →
   Загрузить версию (версия, архитектура и Android API подставятся из имени файла). Или командой на сервере:

   ```sh
   cp HomeVPN_5.1.1.1102_arm64-v8a_api30.apk data/
   ./hvctl release add /data/HomeVPN_5.1.1.1102_arm64-v8a_api30.apk \
       --version 5.1.1.1102 --platform android --abi arm64-v8a --min-sdk 30

   ./hvctl release add /data/HomeVPN_5.1.1.1102_armeabi-v7a_api28.apk \
       --version 5.1.1.1102 --platform android --abi armeabi-v7a --min-sdk 28 --max-sdk 29
   ```

   Для ПК: `--platform linux` (файл `.run`) или `--platform windows` (файл `.exe`).
5. Устройства увидят версию при следующей проверке (после обновления конфига, не чаще раза в 6 часов)
   или сразу по кнопке проверки обновлений в настройках. На Android приложение скачает APK, сверит sha256
   и откроет системное окно установки. При первой установке Android спросит разрешение
   «устанавливать приложения из этого источника» — его надо дать один раз.
   На Windows и Linux по кнопке «Установить обновление» приложение закрывается, и после его выхода
   запускается установщик; закончив, он сам открывает новую версию.

Откатить версию: в панели Версии → Удалить, или `./hvctl release remove ИМЯ_ФАЙЛА`. Устройства, которые уже обновились, назад не откатятся.

## Как добавить и отозвать устройство

В панели админа бэкенда (`https://ДОМЕН/admin/`), вкладка «Устройства». То же умеет команда `./hvctl`
на сервере (подробнее — в README бэкенда).

**Добавить:** «Добавить устройство» → имя. Бэкенд сам создаёт ключи AmneziaWG, выдаёт адрес в туннеле
и прописывает устройство на VPN-сервере. Ключ устройства показывается один раз — его вписывают
в приложение (см. «Как настроить устройство»).

```sh
./hvctl device add tv-zal --key-file /data/tv-zal.key
```

**Отозвать:** «Отозвать» у устройства. Оно перестаёт получать конфиги и обновления
и убирается с VPN-сервера, так что старый конфиг тоже перестаёт работать.

```sh
./hvctl device revoke tv-zal
```

Там же видно, кто сейчас на связи, какая у устройства версия приложения и когда оно спрашивало бэкенд.

## Как сменить сервер

1. Поднять новый сервер приложением Amnezia и выгрузить его конфиг админа: сервер → Поделиться → Полный доступ.
2. В панели: Серверы → «Добавить сервер» → имя и файл конфига админа.
3. Нажать «Сделать основным» у нового сервера.

```sh
./hvctl server add nl2 --from-admin /data/nl2-admin.vpn   # один раз, когда сервер новый
./hvctl server activate nl2                               # переключить все устройства
```

Бэкенд прописывает на новом сервере все устройства сразу при добавлении, и сервер появляется в списке
на устройствах. Устройства перейдут на новый основной сервер при следующем опросе (по умолчанию раз в 6 часов с разбросом),
при следующем подключении или сразу по кнопке **«Обновить сейчас»**. Если старый сервер перестал отвечать,
приложение само замечает мёртвый туннель и идёт на бэкенд за новым конфигом.

Убрать сервер с устройств — «Не выдавать» у сервера в панели (`./hvctl server unpublish ИМЯ`),
название сервера на устройствах — «Название» (`./hvctl server title ИМЯ "Финляндия"`).

Если у того же сервера сменился IP, новый сервер не нужен: «Сменить адрес» у сервера в панели
(`./hvctl server address nl1 203.0.113.9`). Ключи, порт и маскировка остаются прежними, бэкенд проверяет по SSH,
что по новому адресу тот же сервер. Компьютеры перейдут на новый адрес сами; на Android нужно выключить и включить
VPN в приложении — перед подключением оно берёт свежий конфиг.

## Как подтянуть изменения оригинала

```sh
git fetch upstream
git rebase upstream/dev
```

Конфликты возможны только в немногих тронутых файлах оригинала (`git diff --stat upstream/dev`).

Когда у оригинала выходит релиз, которого в ветке ещё нет, панель админа показывает это на вкладке «Версии»
(раздел «GitHub») — пора влить изменения и выпустить новую версию.

## Ограничения

- На Android опрос идёт, пока жив процесс окна приложения. Если система его выгрузила, конфиг обновится
  при следующем открытии приложения или подключении из него.
- Подключения мимо приложения (Always-on VPN, плитка быстрых настроек, включение VPN при загрузке устройства)
  идут с последним сохранённым конфигом, без запроса к бэкенду.
- Включение VPN при загрузке Android работает после того, как VPN хотя бы раз подключали из приложения
  (системе нужно разрешение на VPN и сохранённый конфиг). На устройстве с блокировкой экрана VPN включится
  после первой разблокировки: до неё Android не сообщает приложениям о загрузке.
- На ПК строгий kill switch блокирует запрос к бэкенду, пока VPN выключен. С ним же при недоступном сервере
  обычный интернет не включится.
- Если сервер не отвечает, Android без открытого приложения повторяет подключение к тому же серверу:
  о смене сервера в панели он узнает, когда приложение откроют.
- Если адрес бэкенда не задан, проверка обновлений идёт так же, как в оригинале.
